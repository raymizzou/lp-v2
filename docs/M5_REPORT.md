# M5 按 UTC 日、按市场报告

本批是离线实现与验证；**未部署、未开实盘**，不证明 M4 或连续七天现场验收通过。
批准市场、钱包、代码、资金上限和运行窗口仍由 Ray 明文指定；不自动发现或扩大市场名单。
一个钱包只运行一个执行者，最多三个市场共享全部原 M4 风险和停止规则。

## 使用

```sh
lp-v2 report --state-dir /opt/lp-v2/state --day 2026-11-02 \
  --out /opt/lp-v2/reports/daily-2026-11-02 \
  --credentials-file /etc/lp-v2/credentials.json
```

`--day` 必须是精确 `YYYY-MM-DD`，窗口为 UTC 00:00 到下一天 UTC 00:00。
`--out` 是文件前缀，生成同名前缀的 `.csv` 和 `.json`；已有文件经临时文件原子替换。
输出必须在状态目录外；状态文件、WAL、SHM、控制文件的符号链接/硬链接别名同样拒绝。
新建报告目录为 0700，文件为 0600；既有目录权限由运维负责。报告可能包含保护状态中的请求身份，
发布到公开 issue 前只提取按市场八列数字与结论，不发布完整钱包、订单或本机状态文件。
stdout 只给固定成功/失败说明，不输出凭据、钱包或订单号。

L2 文件内容与 [M4 文档](M4_LIVE.md) 一致，必须为当前用户拥有的普通 0600 文件，无符号链接。
日报只读已有 `key/secret/passphrase/signer_address/wallet_address/signature_type`；
**不读签名私钥或 relayer 文件，不实例化签名客户端，不派生钱包或申请凭据**。
不提供签名/实盘参数。缺少显式匹配 L2 文件时仍导出本地事实，收入显示 UNKNOWN。

## 八列及来源

每个历史日内选中/观察到的市场一行，另有 TOTAL；行附 condition_id、标题和 notes。
金额以精确十进制字符串写 JSON，CSV 为相同值；缺数据用 `UNKNOWN`，不是零。

| 字段 | 定义 |
| --- | --- |
| reward | 请求日官方奖励全部分页，核验市场、钱包、UTC 日与 USDC/pUSD 资产，乘实际资产汇率 |
| rebate | 请求日官方返佣，完整列表或全部分页，核验同样身份和非负金额 |
| paired_profit | 请求日观察到确认回执的 merge 收入减已消耗的毛采购成本；包含早于该日建立的成本历史 |
| fees | 当天自有成交的实际费用；净额只扣一次 |
| inventory_delta | 下一 UTC 日边界的毛浮动盈亏减本日开盘毛浮动盈亏，包含配对但尚未 merge 的持仓 |
| net_profit | reward + rebate + paired_profit + inventory_delta − fees |
| average_occupation | 每市场占用按相邻观察间作阶梯积分，除以 86400 秒 |
| yield_pct_per_day | net_profit / average_occupation × 100；分母为零或未知时 UNKNOWN |

TOTAL 对各金额、平均占用分别求和；收益率按合计净额/合计平均占用计算，不能相加各行收益率。
任一来源未知则该列合计未知，受影响的净额/收益率随之 UNKNOWN。
库存使用已存的 `flat` 或 `observed_boundary` 日初事实；实际观察可能稍晚于午夜，不能伪称精确午夜价。
重启/停机跨日缺基准、闭盘缺观察、缺市场分项、相邻占用间隔超过 60 秒时，相关列 UNKNOWN 并附原因。
不能用最新实盘日的估值替代历史日闭盘，也不能用启动上限代替平均占用。
单市场 M4 身份/流水仍可读；原来没有逐市场字段或风险证明的数据不会被补造。
尚未落定的下单/merge、缺成交累计证明会使受影响财务列 UNKNOWN。

## 安全检查

JSON 的 `safety` 独立于收益，逐项给 `PASS`、`FAIL` 或 `UNKNOWN` 及原因：

- capital：每轮总占用不超过冻结上限且不超过 100；覆盖缺口或旧记录缺证明时 UNKNOWN。
- unpaired：各市场未配对份数不超过计划份数，全市场未配对成本不超过冻结上限一半。
- hedge_ceiling：每张补腿意图/每轮在场或在途补腿价格不超过持久保存的上限。
- duplicate_hedge：每轮同边在场加在途补腿数量不超过同市场对侧未配对数量。
- unknown_duration：列出放置、撤单、merge 未知期间的开始、落定时间/结果和测得秒数，未落定另列。
  **Ray 尚未确定 live UNKNOWN 时长阈值，因此该阈值判断始终 UNKNOWN**，不猜十分钟。

看见违规优先 FAIL；没有违规但缺完整证明时 UNKNOWN。PASS 只证明记录覆盖内的指定数值检查，
不代表政治分类、钱包不存在第二个执行者、实盘网关/链上行为、代码窗口稳定或七天现场验收通过。
未知时长是观察到的持久事实区间，不声称精确链上发生时间。放置可由权威 LIVE 读回落定；
撤单必须等权威 CANCELLED/FILLED 终态，重复撤单保留最早未落定的起点。新读回使用本次观察时间，
不改请求创建/到期时间。旧版本已写入的错误观察时间不能事后重构或改写；旧记录算出的时长
只反映原持久时间戳，其真实期间未被证实。无明确结果不能由超时推断失败。

## 只读与可追溯性

SQLite 使用 `mode=ro` URI 和一个读取事务，读取提交到活动 WAL 的事实；不使用 `immutable=1`，
不 CREATE、不建索引、不写 schema/DB/WAL、不执行写 PRAGMA。SQLite 的正常共享内存读锁可以更新 SHM 读标记；
这不代表追加事件或修改持久账本。JSON 记录 snapshot_seq 与导出时间。

收入每次重新 GET 请求日 `/rewards/user` 与 `/rebates/current`，不使用今日 journal 收入缓存。
HTTP 最终同步传输层复用既有只读审计，非 GET 在发送前拒绝；无重定向或非 GET bootstrap。
分页中断、身份/资产/日期不符、凭据/接口不可用均保留 UNKNOWN 原因，不把部分金额当完整金额。
真实接口能否提供历史返佣、D+1/D+2 收入是否一致仍需授权后的现场验证；文档不把 GET 返回当作最终结算承诺。

日报会读取完整历史以恢复成本并审计 UNKNOWN 区间，内存和导出时间随历史增长；
本批的五秒门禁约束实盘最后一天的一轮，不约束离线报告导出。
实盘轮次仅解码当天占用，按种类/序号 SQL 过滤，UTC 换日和重启刷新下界，未缓存跨轮交易事实。

未来获批现场运行时，可在 D+1 和 D+2 分别重读同一天报告，保留旧输出并比较官方奖励差异。
报告不调度、不 POST、不部署、不发单、不停服务，也不自行关闭验收 issue。
